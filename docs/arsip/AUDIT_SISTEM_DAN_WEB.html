Temuan kritis

Tiga temuan ini mengubah hasil pengukuran, menghapus data, atau mematahkan klaim yang tertulis di dokumen.

K1 Tekan-lepas gelas memalsukan minum dan mematikan alarm Kritis

fsm.h:107-135, fsm.h:161-184

FSM menerima kenaikan berat stabil 30 g atau lebih sebagai isi ulang tanpa menanyakan apakah gelas pernah diangkat. Baseline naik ke berat baru, lalu jari dilepas dan berat turun 35 g. Penurunan itu melewati ambang minum dan tercatat sebagai minum sah. Load cell memang tidak bisa membedakan air yang dituang dari jari yang menekan, tetapi FSM sekarang ikut tertipu tanpa perlawanan.

f = CoasterFSM(empty_cup_weight=130, target_interval_ms=15000)
settle(f, 380, 1000)      # TIMING, baseline 380
f.update(380, 30000)      # ALERT_DRINK aktif
settle(f, 415, 30000)     # tekan gelas +35 g selama 1,5 detik
settle(f, 380, 33000)     # lepas tekanan

Hasil: alarm mati, refill=1, drink=1, total=35 ml, cheat=0. Lima siklus menghasilkan 175 ml palsu, 5 minum, 5 isi ulang, 0 curang.

Suite 21 skenario tidak menangkap ini karena semua kasus curang di suite berhenti di selisih di bawah 20 g. Penguji bisa mematahkan klaim anti-cheat dengan satu jari.

Ada tiga jalan keluar. Yang paling aman mengunci isi ulang agar hanya sah setelah state LIFTED, dengan konsekuensi skenario 8 PRD hilang. Alternatifnya heuristik pembalik: bila berat turun kembali ke baseline lama dalam beberapa detik, refill dibatalkan dan penurunan tidak dicatat. Pilihan terakhir mengakui ini batas fisik dan mencabut klaim anti-cheat yang berlaku umum.

K2 Reset Harian menghapus riwayat hari itu Kritis

web/index.html:768-775

Tombol menjalankan resetStats() lebih dulu, baru saveTodayStatsToHistory(). Fungsi kedua menulis angka nol ke entri hari ini dan menimpa catatan asli. Riwayat dari pagi sampai siang hilang tanpa jejak.

Urutannya bisa dibalik, atau entri hari ini dihapus dari riwayat bila maksud tombol ini memang mengosongkan catatan.

K3 Kalibrasi gelas kosong memicu isi ulang palsu Kritis

fsm.h:44-55

setEmptyCupWeight() menyetel baseline ke angka kalibrasi, lalu memaksa state ke ALERT_REFILL. Bila gelas berisi masih di tatakan, transisi berikutnya melihat berat jauh di atas batas kosong dan mencatat refill yang tidak pernah terjadi.

settle(f, 380, 1000)          # TIMING
f.set_empty_cup_weight(130)   # user menekan Simpan Gelas
settle(f, 380, 3000)          # refill=1, tanpa isi ulang

Ini efek samping Fix Celah 2 yang belum ditutup. Perintah serial c tidak terkena karena memakai berat aktual, tetapi perintah e dan tombol Simpan Gelas di web sama-sama memicunya.

Temuan sedang

Tidak mengubah hasil pengukuran, tetapi merusak umpan balik atau membuat halaman tidak bisa dipakai di perangkat tertentu.

M1 Seluruh log alarm kehilangan warna Sedang

web/index.html:593, CSS 135-140

evCls memotong nama state setelah garis bawah, jadi ALERT_DRINK menjadi ev-DRINK. CSS hanya mengenal ev-ALERT_DRINK dan seterusnya. Semua baris transisi alarm tampil abu-abu, dan baris isi ulang memakai kelas alarm minum yang tidak cocok dengan maksudnya.

Fungsi evCls cukup mengembalikan 'ev-' + st untuk state berawalan ALERT.

M2 Tombol Putuskan USB tidak menutup port Sedang

web/index.html:790-799, 835-854

Tombol putus memanggil close() saat loop baca masih memegang lock reader. Spesifikasi Web Serial hanya menutup port setelah reader.releaseLock(), dan lock baru lepas setelah reader.cancel(). Error yang muncul ditelan catch kosong, port tetap terbuka, lalu percobaan koneksi berikutnya gagal tanpa pesan.

Urutan yang benar: beri tanda berhenti, await reader.cancel(), tunggu loop keluar, baru close().

M3 casing_3d.html rusak di layar ponsel Sedang

web/casing_3d.html, seluruh berkas

Halaman ini tidak punya satu pun @media. Pada lebar 390 px dokumen meluber sampai 562 px, tombol header terdorong keluar, dan tag anotasi 3D berakhir di koordinat negatif. overflow:hidden menyembunyikan scrollbar, jadi kontrol terpotong tanpa bisa dijangkau. Font 9 sampai 10.5 px dan target sentuh di bawah 44 px menambah masalah yang sama di layar sentuh.

Halaman peraga ini lebih aman dipakai dari laptop, atau ditandai desktop-only supaya tidak dibuka dari ponsel saat presentasi.

Kebersihan dan temuan ringan

  • CFG.BASE_INTERVAL di web/index.html:309 tidak pernah dipakai.
  • Manifest mengunci orientasi potret padahal dashboard dua kolom lebih nyaman mendatar.
  • scale.tare(20) berjalan saat boot. Bila gelas sudah di tatakan saat board dinyalakan, titik nol bergeser dan gelas tidak terdeteksi. Panduan hanya memperingatkan untuk perintah t, bukan untuk boot.
  • Mode demo aktif secara default, jadi board baru memberi alarm tiap 15 detik sampai diubah lewat serial.
  • setInsecure() mematikan validasi sertifikat TLS, dan rules Firebase terbuka. Wajar untuk praktikum, tetapi bertentangan dengan klaim HTTPS tanpa catatan.
  • .gitignore menutup .pyc, *.exe, dan test_*.png, tetapi 14 foto WhatsApp dan Materi/ masih ter-track; 47 file berstatus kotor.
  • Tidak ada README untuk orang baru. HANDOFF_AGENT.md ditujukan untuk agent.

Sisi pengguna

  1. Alur yang paling mungkin dicoba saat demo adalah menekan gelas untuk menguji tipuan. Itu justru eksploit K1, jadi tutup dulu atau jelaskan sebelum sidang.
  2. Tombol Reset Harian menghapus riwayat hari itu, bukan memulai hitungan baru.
  3. Simpan Gelas mengambil berat apa pun yang ada di tatakan. Bila gelas berisi air, volume harian meleset sebesar isi gelas. Label sebaiknya menyebut gelas kosong dan menampilkan berat terukur sebelum menyimpan.
  4. Nyalakan board saat tatakan kosong, jika tidak tare boot menggeser titik nol.
  5. Web Serial memerlukan konteks aman. Membuka index.html lewat file:// memblokir manifest dan notifikasi, terverifikasi di konsol. Jalankan lewat server lokal sesuai panduan.
  6. Halaman 3D jangan dibuka dari ponsel dalam kondisi sekarang.
  7. Belum ada satu halaman yang memandu perakitan dan penyalaan dari nol untuk orang baru.

Sisi developer

  1. Tiga port identik, tetapi sinkronisasinya manual. Tidak ada skrip atau CI yang menjalankan ketiga suite sekaligus.
  2. Saat audit, port web tidak punya uji mandiri: kelas FSM tertanam di dalam HTML, jadi tidak bisa diimpor Node dan delapan tombol skenario hanya mencakup skenario PRD. Saya mengekstrak kelas itu secara ad hoc dan 32 asersi lulus, tetapi hasilnya tidak tersimpan. Kelas itu kini sudah diekstrak ke web/fsm.js, diimpor web/index.html lewat <script src="fsm.js">, dengan web/fsm.test.js (30 asersi, 4 skenario regresi K1/K3 bernomor 18-21). Sisa: mirror penuh 21 skenario Python/C++ di JS, dan delapan tombol skenario di web/index.html masih hanya mencakup skenario PRD.
  3. Tambahkan regresi K1 dan K3 ke ketiga port. Tanpa itu, perbaikan bisa hilang diam-diam seperti kasus gerbang stabilitas sebelumnya.
  4. Firmware dan PRD berbeda soal cloud. Pilih satu kebenaran; yang termurah adalah memperbarui dokumen, bukan menambah fitur.
  5. Biner uji_fsm.exe ikut ter-commit dan sudah basi dibanding sumber.
  6. Kegagalan tulis Firebase ditelan tanpa pesan. Saat rules menolak, dashboard tetap terlihat sehat.
  7. ZeroGPT API sekarang membalas 403 berbayar, SciSpace membalas 500. T-Checker masih berfungsi.
  8. Belum ada bukti uji cloud end-to-end; panduan hanya berisi langkah manual.

Yang sudah benar

  • python test_simulation.py: 21 skenario lulus.
  • Harness C++: kompilasi bersih dengan peringatan penuh, 52 pemeriksaan lulus.
  • Regresi JS di web/fsm.test.js: 30 asersi lulus (4 skenario K1/K3, bernomor 18-21).
  • verify_stackup.py: 59 pemeriksaan geometri lulus saat audit ditulis. Per 2026-10-25 menjadi 60, setelah satu pemeriksaan arah pin motor ditambahkan.
  • Kedua halaman: tag seimbang, JavaScript lolos pemeriksaan sintaks, tanpa error konsol selain CORS manifest saat file://.
  • index.html pada 390 px: tanpa overflow dan tanpa teks terpotong.
  • Tidak ada cabang mati atau state tak terpakai di FSM, filter, maupun kontroler adaptif.

Urutan perbaikan

  1. K1 tekan-lepas. Pilih satu jalan keluar, lalu tambahkan skenario regresi di tiga port.
  2. K2 urutan Reset Harian. Tukar dua baris di web/index.html:769-770.
  3. M1 dan M2. Perbaiki kelas log dan tutup port serial dengan urutan yang benar.
  4. K3 kalibrasi. Tolak kalibrasi saat berat aktual jauh di atas angka yang disimpan, atau selaraskan baseline tanpa memaksa refill.
  5. M4 drift dokumentasi. Minimal dua baris CLAUDE.md yang dibaca setiap sesi.
  6. M3 responsive halaman 3D, atau tandai desktop-only.
  7. Kebersihan repo. .gitignore, hapus artefak, logo tak terpakai, dan biner basi.
